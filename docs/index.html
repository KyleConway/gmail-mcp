This is your own Gmail connector for Claude, running on your Cloudflare account. Here's how to finish setting it up. It takes about 20 minutes, and most of that is Google Cloud.

Every connection performs its own Google sign-in and is bound to the account chosen at its consent screen, and that account is then pinned to the first connector that signed it in. Your refresh tokens stay in your own Cloudflare account. The full guide, with every Google Cloud screen, is docs/SETUP.md.

1 Google Cloud

Create a project and switch the Gmail API on.

PROJECT="gmail-mcp-$(openssl rand -hex 3)"
gcloud auth login
gcloud projects create "$PROJECT" --name="gmail-mcp"
gcloud config set project "$PROJECT"
gcloud services enable gmail.googleapis.com

The consent screen and the OAuth client have no API, so these happen in the Cloud console:

  1. Google Auth Platform → Get started: app name, your email, audience External.
  2. Branding: fill in the home page, privacy policy and terms of service links (any pages you control; https://<your-host>/ works as the home page), list each link's domain under Authorized domains, and add a developer contact. Do not upload a logo: it makes Google require verification.
  3. Audience → Publish app. Left in Testing, Google expires every refresh token after 7 days. Published, sign-in shows an unverified-app warning, which is expected.
  4. Clients → Create client → Web application, with one authorized redirect URI: 
    https://<your-host>/callback
    Select Download JSON straight away: the client secret is shown only once.

2 Cloudflare

Deploy, then set the secrets. Each secret put prompts for its value: type the client secret yourself, and never paste it into a chat.

git clone https://github.com/KyleConway/gmail-mcp && cd gmail-mcp
bun install
bun run deploy
./node_modules/.bin/wrangler secret put GOOGLE_CLIENT_ID
./node_modules/.bin/wrangler secret put GOOGLE_CLIENT_SECRET
openssl rand -hex 32 | ./node_modules/.bin/wrangler secret put COOKIE_ENCRYPTION_KEY
./node_modules/.bin/wrangler secret put ALLOWED_EMAILS

Until the secrets are set, the Worker refuses every sign-in.

3 Decide who may sign in

ALLOWED_EMAILS is checked against the address Google reports as verified, after consent and before any grant exists.

ValueWho gets in
emptynobody — fail-closed default
you@gmail.com, work@co.comexactly those accounts
*@your-company.comany account in that domain
*any verified Google account
A grant only ever reaches the mailbox that authenticated it, so widening this list never widens access to accounts already connected. What * hands strangers is the use of your deployment, and your Google client's quota, for their own mail.

4 Connect in claude.ai

In claude.ai, go to Settings → Connectors → Add custom connector, name it (for example Gmail – Personal), and use this URL. Leave the OAuth client ID and secret fields empty: Claude registers itself.

https://<your-host>/mcp/personal
  1. Select Connect, then Approve on this server's dialog.
  2. Choose your Google account. On Google hasn't verified this app, select Advanced → Go to ….
  3. Leave every permission ticked and continue.
  4. Set each tool's permission in the connector's settings: allow reading, require approval for sending.
  5. Ask Claude to run the connector's whoami tool. It should answer with your address.
The connector syncs to Claude Code and the Claude apps. claude mcp add, the MCP Inspector and localhost sign-ins are refused by design: only Claude's own callbacks may sign in unless ALLOWED_REDIRECT_URIS says otherwise. Any single-segment label works after /mcp/, so a second mailbox can use /mcp/family.
The first connector to finish signing in is pinned to that account. If you remove and re-add the connector, sign-in returns a 403 that explains how to reset the pin. If you did not start the sign-in yourself from Claude's Connect button, change nothing.

5 What you get

✓Read — search with Gmail operators, read messages and threads, download attachments
✓Compose — send, reply to everyone with quoting, full draft lifecycle, attachments and inline images
✓Organize — labels including nested ones, batch changes over many messages, reversible trash

Japanese, Chinese, emoji, and right-to-left text survive the round trip: subjects and filenames are RFC 2047 encoded, bodies carry their declared charset.
